# Agent guide

This repo is a single-binary web app: Rust (axum + sqlx/Postgres) on the server,
React + TypeScript in the browser, typed RPC in between. The framework lives in
`crates/northstack`; the application lives in `app/` and `web/`.

## The workflow

Types flow one way, and every step is generated:

```
migration.sql -> Postgres -> app/src/db/schema.rs -> Rust code -> web/src/rpc/ -> React
```

1. Make your change (migration, Rust, React).
2. Run **`just check`** and fix what it reports. Repeat until it passes. It
   applies migrations, regenerates Rust types from Postgres, compiles,
   regenerates TypeScript types from Rust, and type-checks React, in that order.
   It prints only failures, each with a "how to fix" line.
3. Run **`just verify`** before you're done: `check` plus formatting, clippy
   (warnings are errors), all tests, the offline query cache, and the frontend
   build. A change is done only when it passes. Commit the generated files.

Never edit generated files: `app/src/db/schema.rs`, `web/src/rpc/`,
`web/src/routeTree.gen.ts`, `.sqlx/`. CI runs `just ci`, which fails if any of
them is stale.

## Layout

```
crates/northstack/            framework (rarely changed; see "Changing northstack")
app/
  migrations/           SQL migrations (timestamped, append-only)
  src/db/schema.rs      GENERATED from Postgres: a struct per table, an enum per enum type
  src/lib.rs            build(): registers every feature
  src/state.rs          AppState (db pool, config)
  src/features/<name>/  one folder per feature:
    types.rs            API inputs and query-specific outputs (#[derive(TS)])
    db.rs               ALL SQL for the feature, via sqlx::query!/query_as!
    procedures.rs       RPC handlers
    jobs.rs             background jobs and their handlers
    mod.rs              rpc(), jobs(), cron() registration
  tests/<name>.rs       integration tests through the HTTP router
web/
  src/rpc/              GENERATED client (`api`) and types. Never edit.
  src/routes/           pages, file-based (TanStack Router). One file = one URL.
  src/routeTree.gen.ts  GENERATED route tree. Never edit.
  src/components/       shared components (states.tsx: pending/error/not-found)
  src/main.tsx          QueryClient + router setup
```

`app/src/features/notes` is the reference implementation. Copy its patterns.

## Recipes

| Task | Command |
|---|---|
| Check while working (regenerates everything) | `just check` |
| Before you're done | `just verify` |
| New migration | `just migration <name>`, edit the printed file, `just check` |
| New feature skeleton | `just new-feature <snake_name>` |
| Start the dev database over | `just db-reset` |
| Run backend / frontend | `just dev` / `just web-dev` |

## Database types

`app/src/db/schema.rs` has one struct per table (`notes` → `Note`) and one enum
per Postgres enum (`note_priority` → `NotePriority`), generated by `just check`.
Use them in queries and return them from procedures. Conventions, set with SQL
comments in a migration:

- `COMMENT ON TABLE/COLUMN ... IS '...'` becomes documentation in Rust and TypeScript.
- `@private` in a column comment keeps the column out of JSON and TypeScript
  (password hashes, internal flags). Use it for anything the browser must not see.
- `@name(Person)` in a table comment overrides the struct name (`people` → `Person`).
- `@skip` in a table comment skips the table.

Nullable columns become `Option<T>`. Supported types: bool, int2/4/8, float4/8,
numeric (BigDecimal, a string in TS), text/varchar, uuid, timestamptz, timestamp,
date, time, json/jsonb, bytea, enums, and arrays of these. `just check` lists
any unsupported column.

When a table gains a column, every `query_as!(Table, ...)` must select it: the
compiler lists each query to update. Query-specific shapes (joins, aggregates,
inputs) are written by hand in the feature's `types.rs`.

## Adding a procedure

1. Define input and output structs in `types.rs` with
   `#[derive(Debug, Clone, Serialize, Deserialize, TS)]` and
   `#[serde(rename_all = "camelCase")]`. Optional input fields:
   `#[serde(default)] #[ts(optional)] pub field: Option<T>`.
   Use `()` as input for procedures without input (TS: `null`).
   Use `Uuid` for ids (TS: `string`).
2. Write the SQL in `db.rs` with `sqlx::query_as!`, returning generated row
   types where possible (`query_as!(Note, ...)`). For optional filters use
   `($1::text IS NULL OR col = $1)`. Enum columns need a type hint:
   `SELECT priority AS "priority: NotePriority"` and `priority as NotePriority`
   for parameters. Take `impl PgExecutor<'e>` when the query must work inside a
   transaction.
3. Write the handler in `procedures.rs`:
   `pub async fn name(ctx: Ctx<AppState>, input: In) -> RpcResult<Out>`.
   Validate with `northstack::ensure!(cond, "message")`. Return
   `RpcError::not_found(..)` etc. for expected failures. `?` on sqlx errors maps
   `RowNotFound` → NOT_FOUND, unique violations → CONFLICT, else INTERNAL
   (logged, never leaked to the client).
4. Register in the feature's `rpc()`: `.query("feature.name", procedures::name)`
   for reads, `.mutation(...)` for writes. Names are dot-separated camelCase.
5. `just check`, then use it from React through `api` (see "Frontend" below).
6. Add tests in `app/tests/<feature>.rs` (see `app/tests/notes.rs`).

## Frontend

The frontend is a client-rendered SPA: TanStack Router for pages, TanStack Query
for server data, and the generated `api` object for every call.

**Pages.** A file in `src/routes/` is a page:
`index.tsx` → `/`, `about.tsx` → `/about`, `notes.$noteId.tsx` → `/notes/:noteId`,
`__root.tsx` is the layout. Export `const Route = createFileRoute("/path")({...})`.
The route tree is generated; links and params are type-checked
(`<Link to="/notes/$noteId" params={{ noteId }} />`).

**Data: load in the loader, read with suspense.** Every page that shows server
data follows this pattern, so it renders with data and never shows spinners:

```tsx
export const Route = createFileRoute("/notes/$noteId")({
  loader: ({ context: { queryClient }, params }) =>
    api.notes.get.ensureData(queryClient, { id: params.noteId }),
  component: NotePage,
});
function NotePage() {
  const { noteId } = Route.useParams();
  const note = api.notes.get.useSuspenseQuery({ id: noteId }); // never undefined
}
```

Use `useQuery` (not suspense) only for data that is optional or loaded on demand
inside a page.

**Mutations declare what they invalidate:**
`api.notes.create.useMutation({ invalidates: ["notes"] })`. Targets are a
namespace (`"notes"` = every notes query) or one query (`"notes.list"`).
Don't invalidate a query for something you just deleted; target the list instead.

**State in the URL.** Filters, search, tabs and pagination go in search params
via `validateSearch` + `loaderDeps` (see `routes/index.tsx`), so they survive reloads
and can be shared. Use local state only for form inputs and UI toggles.

**Errors.** Loaders turn `NOT_FOUND` into `throw notFound()`. Everything else
falls through to the error component, which has a retry button. Show mutation
errors inline (`mutation.error.message`). Check codes with `isRpcError(e, "CONFLICT")`.

**Don't:** call `fetch` directly, build query keys by hand, or put server data
in `useState`. All server data goes through `api`.

## Adding a background job

1. Define a serializable struct and `impl northstack::Job` with a stable
   `KIND = "feature.verb"`. Optionally set `MAX_ATTEMPTS` and `TIMEOUT`.
2. Write `async fn handler(state: AppState, job: T) -> anyhow::Result<()>`.
   **Handlers must be idempotent**: a job may run more than once.
3. Register in the feature's `jobs()`: `.register(jobs::handler)`.
4. Enqueue with `northstack::enqueue(&mut *tx, &Job { .. })` **inside the same
   transaction** as the write that causes it.
5. CPU-heavy work goes through `northstack::cpu::spawn(move || ...).await?`, never
   directly in async code.
6. Test with `app.jobs_ref().run_pending(&pool, state).await`.

## Adding a cron entry

Add to the feature's `cron()`:
`Cron::new().add("feature.name", "0 0 7 * * *", |at| SomeJob { .. })`.
Expressions have a seconds field and are UTC. Cron only enqueues a job; it is
safe with any number of replicas. Test with `app.cron_ref().fire(&pool, name, at)`.

## Database rules

- Migrations are append-only. Never edit an applied migration.
- Make schema changes backward compatible (expand, then contract): during a
  rolling deploy, old and new binaries run against the same schema.
- Prefer Postgres enums and `CHECK` constraints for fixed sets of values: enums
  flow into Rust and TypeScript, so adding a value makes the compiler point at
  every place that must handle it.

## Don'ts

- Don't edit generated files (`app/src/db/schema.rs`, `web/src/rpc/`,
  `web/src/routeTree.gen.ts`, `.sqlx/`).
- Don't redefine a table's row type by hand; use the generated one.
- Don't build SQL strings with `format!`. Use bind parameters.
- Don't hold a transaction open across slow I/O (HTTP calls, big CPU work).
- Don't store state in memory that must survive restarts or be shared across
  replicas: use Postgres.
- Don't add dependencies when the standard library or an existing dependency
  covers it.

## Changing northstack

The framework is small (`crates/northstack/src`, ~2.5k lines) and fully tested
(`crates/northstack/tests`). Change it when a pattern repeats across features, keep
the public API small, and add a test for every behavior change.
